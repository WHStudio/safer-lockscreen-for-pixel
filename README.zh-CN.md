# Safer Lockscreen

Safer Lockscreen 是一个面向 Google Pixel 的小型、隐私优先的 Android 应用。手机锁定时，它阻止下拉快捷设置和通知栏，也可以关闭电源菜单。

Pixel 原版系统没有关闭锁屏下拉的开关。任何人拿到已锁定的手机，都可以下拉并切换飞行模式、WLAN 或移动数据。Android 17 的**锁定快捷设置连接**只会冻住少数连接类开关。通知栏本身仍能拉开，其他开关仍可使用。本应用针对的就是这个缺口。

包名：`com.whstudio.saferlockscreen`。

本项目与 LSDroid 或 Cerberus Lock Screen Protector 无关，也不包含其代码。它只使用 Android 的公开 API。

## 它做什么

防护只在 `KeyguardManager.isDeviceLocked()` 为真时运行。也就是说，Android 仍要求 PIN、图案或密码。解锁之后，快捷设置和电源菜单恢复正常。智能解锁和延长解锁视为已解锁，应用不会干预，以免妨碍你自己使用快捷设置。

手机锁定时：

- **在锁屏上阻止快捷设置**（打开防护后默认开启）会收起通知栏和快捷设置。
- **在锁屏上阻止电源菜单**（默认开启）会关闭关机 / 重新启动菜单。
- 锁屏上的**紧急呼叫**按钮不会被挡住。紧急拨号或个人安全 SOS 界面打开时，不会按返回键，以免掐断通话。因此这条路径有时仍可能碰到快捷设置。
- 时钟、PIN 键盘、图案、指纹区域，以及锁屏的其余部分都不会被盖住。
- 应用不会关闭屏幕。

防护只有一种行为。透明的无障碍悬浮层盖住屏幕顶部边缘，使下拉通知栏的滑动无法开始。只有快捷设置或通知栏真正展开并盖住屏幕大部分时，应用才会收起它。电源菜单用另一个开关以同样的方式关闭，不会熄灭屏幕。

### 为什么这样实现

没有公开的应用 API 可以关闭锁屏上的通知栏。隐藏的状态栏 API 需要系统签名，本应用不使用它们。

AOSP 会在锁屏显示的整段时间里保留一个标题为 `NotificationShade` 的 System UI 窗口，包括通知栏收起的时候。锁屏通知也画在同一个窗口里。因此，仅仅看到这个窗口或通知列表，不会被当成“快捷设置已打开”。

服务会响应窗口事件，并在屏幕亮着且设备锁定时每隔一小段时间再检查一次。它只根据系统窗口的身份来判断界面：

- 窗口标题和窗格标题
- 类名
- 视图 id，例如快捷设置的框架
- 窗口状态变化事件携带的短标题

它不读取通知正文、短信或密码，也不调用截屏 API。

顶部边缘的遮罩是无障碍悬浮层（`TYPE_ACCESSIBILITY_OVERLAY`），高度只覆盖状态栏下拉区域，包括屏幕挖孔。从这里开始的触摸会被吃掉。其余位置的触摸会穿透。屏幕关闭、设备解锁或防护关闭时，遮罩会被移除。

通知栏窗口位于普通应用窗口之上。无障碍悬浮层是无障碍服务盖住它的受支持方式。如果滑动仍然拉开了面板，只有当该面板盖住屏幕大部分时才会被收起。看到锁屏、键盘锁、收起的 `NotificationShade` 窗口或 `ShadeScene`，都不会关闭屏幕。

防护不使用设备管理器，也不调用 `DevicePolicyManager.lockNow()`。如果设备管理器仍处于启用状态，必须先停用，Android 才允许卸载。不能清除数据，也不能重置密码。

无障碍服务、设备管理器接收器、开机广播和应用本身都标记了 `directBootAware`。设置保存在设备受保护存储中。重启之后、首次解锁之前，已启用的服务仍可守护锁屏。清单中的接收器会监听 `LOCKED_BOOT_COMPLETED`、`BOOT_COMPLETED` 和 `USER_UNLOCKED`。

没有前台服务，也没有常驻通知。系统会保持已启用的无障碍服务运行。

## 权限

| 权限或能力 | 原因 | 如何关闭 |
| --- | --- | --- |
| 无障碍服务 | 识别通知栏、快捷设置或电源菜单是否出现，收起真正展开的面板，并挡住顶部下拉。Android 会警告该服务可以观察窗口。本应用只用这些信息来识别上述系统面板。 | 设置 → 无障碍 → Safer Lockscreen → 关闭 |
| 设备管理器（如果仍在启用） | 防护不使用它。设备管理器仍启用时，必须先停用才能卸载。 | 在应用内点**停用设备管理器**，或到设置 → 安全 → 设备管理应用 |
| `RECEIVE_BOOT_COMPLETED` | 在开机和首次解锁时复查防护。安装时授予，没有弹窗。 | 卸载应用 |
| 网络 | **未申请。** | — |

没有广告、统计、崩溃上报、Firebase 或其他追踪器。没有截屏 API。没有内容提供器，也不会把屏幕内容广播给其他应用。已关闭备份和设备间数据传输。

设备管理器仍处于启用状态时，Android 不允许卸载。请先停用设备管理器，再卸载。

在 Android 13 及更新版本上，侧载应用常常要先允许受限制的设置，无障碍开关才可以打开：

1. 设置 → 应用 → Safer Lockscreen
2. 打开菜单（三个点）→ **允许受限制的设置**
3. 回到应用，打开无障碍设置
4. 打开 **Safer Lockscreen**

应用内的说明与此相同。

## 在手机上设置

1. 安装调试 APK（见下文）。
2. 打开 **Safer Lockscreen**。第一次打开主界面时，请阅读风险说明。确认按钮会禁用 5 秒，然后需要你点一下。对话框不会自己关闭，点外面或按返回键也不会关闭。除非清除应用数据或重新安装，否则不会再出现。
3. 启用**无障碍服务**。请阅读它的说明。说明与上面的段落一致。
4. 打开**拦截锁屏面板**。两个功能开关都可以保持开启。
5. 如果界面显示设备管理器仍在启用，请停用它。
6. 如果还没有 PIN、图案或密码，请先设置一个。仅滑动解锁不算锁定。
7. 锁定手机，试着从顶部向下滑。快捷设置不应保持打开。屏幕应保持亮着，以便输入 PIN。使用锁屏上的紧急呼叫按钮，确认它仍能打开。

## 编译与安装

需要：

- JDK 17 或更新版本（项目编译目标为 Java 17）
- Android SDK Platform 37（Android 17）和 Build-Tools 37.0.0
- `ANDROID_HOME`，或在 `local.properties` 中设置 `sdk.dir=...` 指向 SDK

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
```

调试 APK：

```text
app/build/outputs/apk/debug/app-debug.apk
```

在已开启 USB 调试的设备上安装：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`minSdk` 为 31（Android 12）。`targetSdk` 和 `compileSdk` 为 37（Android 17）。仓库包含 Gradle Wrapper。仓库中没有签名密钥。调试 APK 使用 Gradle 在本机生成的 debug 密钥签名。

GitHub Actions 会在 push 和 pull request 时编译调试 APK 并运行单元测试。工作流会自行安装 SDK 平台 `android-37.0`。

## 如果已经无法正常使用手机

本应用未经充分测试和验证，有小概率导致无法正常解锁。顶部遮罩仍可能妨碍锁屏上的电源菜单。不要指望在锁屏上长按电源键来恢复。

1. 如果这台手机以前已经授权过 USB 调试，把它连到电脑上，然后执行：

   ```bash
   adb uninstall com.whstudio.saferlockscreen
   ```

2. 否则，按住电源键大约 30 秒，直到手机重新启动，以此强制重启。不要使用锁屏上的电源菜单。

3. 出现 Google 的 G 标志时，按住音量下键，直到手机启动完成。这会进入安全模式。

4. 在安全模式中，如果设备管理器仍在启用，请先停用它（可在应用内，或到设置 → 安全 → 设备管理应用）。然后卸载 Safer Lockscreen。重启手机即可退出安全模式。

## 已知限制

- 通知栏或电源菜单可能在被关闭前短暂闪现。挡住常见下拉动作的是顶部遮罩。它无法保证相对 System UI 完全没有时间差。
- Android 16 及更新版本的 System UI（scene container / Flexiglass）在锁屏显示时会一直保留通知栏窗口，包括通知栏收起的时候。应用用顶部边缘挡住下拉，只有面板盖住屏幕大部分时才会收起它。它不会关闭屏幕。
- 非 Pixel 系统的行为可能不同。识别逻辑包含一些常见标题（“控制中心”，以及简体中文的系统字符串），但本应用针对的是原版 Pixel Android 17。
- 紧急拨号界面打开时，不会按返回键。如果有人先打开紧急呼叫，而收起面板没有赶上，仍可能碰到部分开关。
- 通过电源键进入紧急呼叫会经过电源菜单。拦截该菜单可能打断这条路径，顶部遮罩也可能妨碍电源菜单。锁屏上单独画出的紧急呼叫控件不会被盖住。不要指望在锁屏上长按电源键来恢复。
- 知道 PIN 的人不会被拦住。手机没有屏幕锁定时也帮不上忙。它不是设备追踪或远程清除工具。这些功能故意不存在。
- 另一个无障碍服务可能与遮罩冲突。使用 TalkBack 的人应先试过这种组合，再依赖它。
- 息屏显示不会被遮住：屏幕不处于可交互状态时会移除遮罩，因此不会盖住息屏显示，也不会吃掉整块点击唤醒区域。顶部边缘仍可唤醒手机。

## 隐私

应用没有网络权限，也没有打开网络连接的代码。偏好设置不会离开这台手机。日志只记录执行过的动作（`dismissShade`、`dismissPowerMenu`）和异常类名。不会记录窗口标题或通知正文。
